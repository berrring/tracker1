# SafeTrack workspace instructions

- Continue the existing Flutter project and preserve the Android, iOS and firmware sources.
- Keep demonstrations fictional. Keep real phone numbers, credentials and device data out of source, fixtures, logs and deployed assets.
- Check the remaining five-hour Codex usage limit when the usage tool exposes it. At 5% remaining or less, stop starting new work and save completed work.
- Before a checkpoint, update PROGRESS.md with completed work, unfinished work, known issues and exact next steps.
- Inspect the staged changes before committing. Exclude credentials, phone numbers and generated output unless the user explicitly requests a specific deployment bundle such as public/.
- Commit and push to the authorized GitHub remote after each major milestone. Use a separate checkpoint branch for unfinished or unverified work. Never force-push.
- When usage information is unavailable, commit and push after each completed milestone. Verify the remote ref matches the local commit and record the hash.
